> **本文件是主调度 Agent 与三个子 Agent（建模手/代码手/论文手）的硬性运行规则。** 用 LangGraph/AutoGen 实现时，以下每条都需落到 system prompt / 图配置 / 校验器代码中。
>
> **状态**：v2.0，2026-08-22。新增 §八 物理手 + §九 知网收集者。任何改动需同步更新此文件 + `_README.md` 第三节。

## 一、工具使用边界（read_md vs rag_search_knowledge）

**原则：默认 RAG 片段检索，全文读取是白名单特权。**

| 场景 | 使用工具 | 原因 |
|---|---|---|
| 查询某题型解法、某年评述、某概念、某扣分点 | `rag_search_knowledge`（片段） | 避免把整篇 md 拉进上下文 |
| 走选型决策树（00_国赛总览 §2.2） | 允许 `read_md` 全文 | 决策树是树形结构，片段切割会破坏逻辑 |
| 查完整赛题速查表（05） | 允许 `read_md` 全文 | 表格整体才有意义，且很小 |
| 启动时读 `_README.md` / `_AGENT_PROTOCOL.md` | 允许 `read_md` 全文 | 协议本身必须完整可见 |
| 其余任何情况 | 强制 `rag_search_knowledge` | 违反视为违规，主调度打回 |

**read_md 全文白名单（唯一）：** `00_国赛总览`、`05_历年赛题速查表`、`_README.md`、`_AGENT_PROTOCOL.md`。其他 8 个 md 一律 RAG 片段。

## 二、各子 Agent 检索优先级（共享知识库）

| Agent | 优先检索顺序 | 核心职责 | 输出产物 |
|---|---|---|---|
| **建模手** | 00 → 01 → 02 → 03 → 06 | 定题型、定假设、建数学模型 | 题目分析、题型确认、假设集合(带依据)、符号表、数学模型(目标/约束/求解思路)、题外资料清单 |
| **代码手** | 03 → 06 → 05 → 08 → 00 | 算法实现、求解、可视化 | 可运行代码、结果数值、收敛/误差分析、每子问可视化图 |
| **论文手** | 04 → 06 → 09 → 07 → 05 | 论文写作、插图 | 各章节草稿、插图需求清单、摘要(带具体数字)、参考文献 |

> 示例（建模手）：优先检索 00、01、02、03、06；遇到模型疑问可主动读取其他 md。建模手完成后，通过 agent-to-agent 消息把产物发给代码手，同时抄送主调度。

## 三、Agent 间消息传递约束（防上下文爆炸）

**铁律：Agent 之间只传递"加工后的业务产物"，禁止传递知识库原始文本。**

- ✅ 允许传递：假设清单、公式、目标函数、约束、任务清单、数值结果、图表需求、论文段落草稿。
- ❌ 禁止传递：从 md 里读到的整段原文、RAG 检索返回的原始片段、知识库整文件内容。
- 📐 格式规范：消息体用结构化文本（Markdown 表格 / 编号列表 / 关键公式行），每条 ≤ 若干行，指向性明确。

**示例（正确）**
```
建模手 → 代码手：
任务：实现问题二求解
输入：附件数据 data.xlsx（第 3-8 列）
模型：min C = Σ x_i·C_i, s.t. Σ x_i ≤ 5, x_i∈{0,1}
求解思路：0-1 整数规划，用 LINGO 验证结构，Python scipy.optimize.milp 精算
输出要求：最优解 + 目标值 + 各方案对比表 + 折线图
```

**示例（违规，禁止）**
```
建模手 → 代码手：
「03_ABC各题型解法特点.md 里 B 题解法第 3 条说：先证明可行性/上下界，
2018B 先证明...（一整段原文粘贴）...请按此实现。」
```

## 四、主调度 Agent 结构化校验清单（逐条强制）

主调度收到各 Agent 产物后，按此清单逐条检查，**不满足即打回对应 Agent 返工**（打回时指明哪条未过）。

| # | 校验项 | 通过标准 | 打回给 |
|---|---|---|---|
| 1 | 题型判定 | 明确输出"输出是数/序列/排名/方程/规律"之一，且与题目匹配 | 建模手 |
| 2 | **B 题是否无脑套用 0-1 规划** | B 题先判题型（统计/几何/物理/概率/0-1），近五年 0-1 已退场，除非确认是纯离散决策 | 建模手 |
| 3 | 假设逐条依据 | 每条假设要么是"标配"，要么带物理/文献依据；无"把结论假设掉"的扣分项 | 建模手 |
| 4 | 数学模型完备 | 有目标函数 + 约束 + 求解思路，符号表齐全 | 建模手 |
| 5 | 代码可运行 | 代码无语法错、能出数值结果，关键结论与模型一致 | 代码手 |
| 6 | **可视化** | 每个子问至少 1 张图，图后紧跟结论句 | 代码手 |
| 7 | 误差/灵敏度分析 | 结果含至少一种检验（R²/F 检验/p 值/MRE/灵敏度/残差图） | 代码手 |
| 8 | **摘要含具体数值** | 摘要逐问"方法+模型+具体数字"，无空泛表述 | 论文手 |
| 9 | 扣分清单自查 | 已对照 `09_国赛写作扣分错误清单` 逐条自查，无违例 | 论文手 |
| 10 | AI 使用声明（2025 新规） | 明写"未使用 AI"或明写工具+诊断 | 论文手 |

## 五、迭代终止防护（防死循环）

- **最大迭代轮次：3 轮**（每轮 = 一次"打回 → 返工 → 重新提交"）。
- 超过 3 轮仍未全部通过校验：**强制终止**，输出当前版本 + 在最终产物头部标注 `[遗留风险]` 列表（未过校验项 + 原因）。
- 单 Agent 内部自迭代也设上限：建模手/代码手/论文手各自最多自检 2 次再交主调度。
- 禁止 Agent 间无目的互相辩论；只有主调度触发的打回才允许再次迭代。

## 六、RAG 检索作用域（跨文档噪声防护）

**主调度在派发任务前，根据题型预先限定每个 Agent 的检索文件 scope，禁止全库搜索。**

| 题型 | 物理手 scope | 建模手 scope | 代码手 scope | 论文手 scope |
|---|---|---|---|---|---|
| A 题（机理） | 11,10,03,00 | 00,01,02,03,06 | 03,05,08 | 04,06,09 |
| B 题（离散/优化/几何/概率/物理） | 11,10,03,00 | 00,01,02,03,06 | 03,05,08 | 04,06,09 |
| C 题（数据） | 11,03,00 | 00,01,02,03,06 | 03,05,08 | 04,06,09 |

> 说明：目前 scope 主要靠"文件层面"隔离。若实现片段级 RAG，再加**关键词白名单/黑名单**过滤，例如做 2025B 物理光学题时，把"PBC、空间哈希、仿真 bug"这类词从代码手检索的召回中剔除，避免 08 的 PBC 案例混入。

## 八、物理手约束规则（新增）

### 8.1 定位与职责

物理手在**拆题手之后、建模手之前**运行。职责是从第一性原理出发分析题目中的物理/几何/统计机理，给出模型类型的判定和必须遵守的物理约束，防止建模手套用错误模型。

### 8.2 检索优先级

11_物理建模方法论 → 10_FP反演优化策略 → 03_ABC各题型解法特点 → 00_国赛总览

### 8.3 工具边界

- 允许 `rag_search_knowledge` 检索片段（优先检索 11_物理建模方法论、10_FP反演优化策略）
- 白名单文件可 `read_md` 全文
- 禁止执行代码（物理手不做数值求解）

### 8.4 输出约束

物理手必须输出结构化 JSON，包含：
1. **物理情景分析**：从第一性原理出发的详细分析
2. **模型类型判定**：DAE/PDE/ODE/优化/统计
3. **自由度分析**：DOF 数 + 约束数 + 完全/欠/过约束
4. **控制方程**：物理定律对应的数学表达式
5. **边界条件**：初始条件和边界条件
6. **约束清单**：所有必须满足的几何/物理约束
7. **常见陷阱**：该问题最容易犯的物理错误
8. **给建模手的指令**：必须遵守的物理约束

### 8.5 硬检查规则（主调度执行，不依赖 LLM）

主调度收到物理手输出后，执行以下硬检查。任一不通过则打回物理手返工：

| # | 检查项 | 通过标准 |
| H1 | 模型类型有无判定 | 明确输出 DAE/PDE/ODE/优化/统计 之一 |
| H2 | 自由度分析 | 明确写了 DOF 数和约束数 |
| H3 | 边界条件 | 至少列出 1 条边界条件 |
| H4 | 约束清单 | 至少列出 1 条约束 |
| H5 | 常见陷阱 | 至少列出 1 个陷阱 |
| H6 | 不自相矛盾 | 完全约束系统不应含目标函数；欠约束系统应给出额外物理原理 |

### 8.6 反馈回路

- 硬检查失败 → 打回物理手（带具体未通过项）
- 建模手/代码手/论文手阶段的物理相关校验失败 → 通过 `p_fb` 打回物理手
- 物理手最多返工 3 轮

## 九、知网收集者规则（新增）

### 9.1 定位与职责

知网收集者在**拆题手之前**运行。职责是自动搜索 CNKI（知网）上与题目相关的学术论文，构建临时知识库，供后续角色参考。

### 9.2 工具边界

- 仅使用 CNKI 搜索 API（内置模块，非 Agent 工具）
- 不调用 LLM，不执行代码
- 搜索策略：根据题目文本自动生成多组关键词，覆盖不同搜索角度

### 9.3 输出

- 临时知识库 Markdown 文件，保存在 `work_dir/temp_kb/` 目录
- 包含论文标题、作者、来源、摘要等信息
- 最多 5 篇论文，有摘要的优先

### 9.4 反馈回路

- 知网检索失败或结果为 0 篇 → 允许跳过，不影响后续流程
- 论文手/校验手发现参考论文不相关 → 通过 `cnki_fb` 打回知网收集者重新搜索
